## Qué vas a lograr

Que tu agente guarde lo que importa (quién es el cliente, qué pidió) en una base SQL y lo recuerde aunque el chat se reinicie o le escriban desde otro canal.

## Pasos

1. Crea la base y su tabla. Con el CLI:

```bash
easybits db create clientes
easybits db query clientes "CREATE TABLE clientes(telefono TEXT PRIMARY KEY, nombre TEXT, nota TEXT)"
```

2. En [Flota](/dash/flota) abre tu agente → canal **WhatsApp** → **Qué puede hacer** → **Bases de datos** → **Escritura**.
3. En **¿A cuáles entra?** enciende sólo `clientes`. Sin ninguna elegida entra a **todas** tus bases.
4. Agrégale a las **Instrucciones** cuándo usarla, por ejemplo: *"Cuando un cliente te diga su nombre, guárdalo en la tabla clientes. Antes de saludar, búscalo por su teléfono."*

## Hazlo con tu agente

El prompt de abajo hace los cuatro pasos sin abrir el panel. Para probarlo: dile tu nombre por WhatsApp, borra el chat y vuelve a escribirle. Si te saluda por tu nombre, la memoria ya no depende del contexto. Confírmalo tú mismo:

```bash
easybits db query clientes "SELECT * FROM clientes" --json
```

<Callout type="info">
Dale el nivel mínimo que necesite: **Lectura** para un catálogo, **Escritura** para registrar clientes. **Borrado** casi nunca hace falta en un canal con clientes.
</Callout>

## Qué acabas de aprender

La memoria del chat se compacta y se pierde; la base no. Y el acceso es por canal y por base: el agente no puede leer lo que no le diste. Esta lección se marca hecha cuando **tu cuenta tiene una base de datos**.
